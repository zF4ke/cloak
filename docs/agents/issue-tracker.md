# Issue tracker

Use GitHub Issues in `zF4ke/cloak`. Read an issue with `gh issue view <number> --repo zF4ke/cloak`. Check existing issues before creating duplicate work. Record the concrete problem, intended result and relevant verification. Link the issue in implementation commits when there is one. Close it only after the behavior is implemented and verified.

The initial desktop implementation is defined in `docs/specs/desktop-project-manager.md` and the dated decisions in `docs/adr/`. These are the spec sources when reviewing this feature branch against `08b1591`.
